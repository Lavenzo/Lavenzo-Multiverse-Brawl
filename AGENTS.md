# Contributor handover

Read README.md and DEVELOPMENT_STATUS.md before editing. Milestones 1, 1.5, 2 and 3 are implemented: Stage 1 is four waves plus the Kingpin boss. Stop for user review before starting Stage 2 or any later milestone. Keep all continuity information in local files.

- Preserve ES modules, Vite, Canvas, and a backend-free architecture. Extend working modules rather than rewrite them.
- InputManager is the only keyboard listener owner for game controls. Keep arrows for movement, A punch, S kick, D special, W strong, Space jump, Enter confirm, Escape pause, P developer tools. No WASD movement or function-key shortcuts.
- Keep simulation in entities/engine and drawing in Renderer/UI. Character attributes belong in data definitions. Future combat must distinguish lane position, jump height, bodies and hitboxes.
- Share CharacterRenderer between gameplay and selection. Keep world positions in logical 960×540 coordinates independent of Canvas pixel size. Respect ResizeObserver and the 16:9 viewport. Cache static scenery; preserve HUD nodes rather than rebuilding DOM every frame.
- Optional artwork paths/frames/dimensions belong in data/assets.js and load through AssetManager. Always preserve vector fallback. Keep strong/special simulation state names compatible with the existing test API; render aliases strongAttack/specialAttack are supported.
- Attack presses are edge-triggered and cooldown-controlled. Clear input on transitions and focus loss.
- Damage belongs in CombatSystem/Fighter, never rendering. Each swing records contacted target IDs, including invulnerable contacts. Preserve facing, lane, height, active-window and body-collision separation. Dead actors cannot attack; hits cancel attacks and apply timed invulnerability. The only exception is boss attack profiles flagged `armor`: they take damage but keep going. Profiles flagged `guard` are invulnerable through windup and active.
- Enemy identities/tiers and attacks live in data/enemies.js; wave composition and the Stage 1 encounter (`cityBoss`) live in data/waves.js. Roman/Seth must remain regular. Venom is a mini-boss available for developer testing, not the Stage 1 boss. Kingpin (tier `boss`) is the Stage 1 boss. Difficulty is independent of identity and stage number.
- Bosses use entities/Boss.js, which extends Enemy and reuses beginAttack, CombatSystem and Fighter damage; never add a separate combat path. Boss rules (moves, timers, phase-2 modifiers) are data in `config.boss`. Keep every boss move telegraphed (windup ≥ ~0.38 s, ground warning for charge/slam), keep the post-contact backoff longer than player invulnerability, and drop follow-ups after contact. Re-run the boss fairness simulation after balance changes.
- StageManager owns the stage phases: waves → warning → entrance → boss → defeated → cleared. Only the encounter boss (`waves.boss`) clears the stage. There is no Waves Cleared screen; `finishStage` shows STAGE 1 CLEARED and, in normal mode only, saves best score and `clearedStages`. Never unlock Stage 2 while it is unimplemented.
- Clear All deliberately enters developer sandbox. Select/restart a wave resumes progression. Keep developer difficulty limited to validated 0.5–2 values and manual spawns. Never save developer scores or unlock unfinished stages.
- Developer actions must use validated Game methods, never mutate through UI or test-only shortcuts. Restrict developer shortcuts to Developer Mode. Reset cheats/API when returning to normal mode; never save developer progress. Boss tools are `startBossEncounter({intro, restore})`, `restartBossFight`, `setBossHealth` (whole numbers 1..max), `defeatBoss`, and restart via `developerAction('restart')`; Shift+3 jumps to the encounter.
- Unsupported stages must remain visibly unavailable. Never represent previews or placeholder configurations as finished stages.
- Use data-testid for menu controls and guarded gameTestAPI for browser automation. Keep optional assets/storage failures nonfatal.
- Run npm run build and npm test after functional changes. Add meaningful behavioral checks when expanding simulation. Update DEVELOPMENT_STATUS.md with results, known limits and next steps.
- Do not push without user approval. Do not add external character assets or audio without authorization.
